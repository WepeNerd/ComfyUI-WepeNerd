# H3 prompt enhancer reassessment — 7 September 2026

The enhancer has a sound prompting philosophy, but an incomplete compilation contract. Improve its knowledge of the requested workflow, make formatting and preservation explicit, and detect incomplete output before adding more creative rewriting.

This records the assessment before implementation. The subsequent code/skill update and Qwen rewrite checks are documented in the README and adjacent evaluation JSON; the findings and proposals below describe the original baseline. This assessment combined source inspection, existing tests, a simulated backend failure, MiniMax's published guides, and targeted live Hivemind reads. No H3 videos were generated.

## What it actually does

`WN_H3PromptEnhancer` accepts an LLM configuration, text, and four selectors: generation mode, task, action detail, and enhancement level. It concatenates the selectors into the user message, sends the entire H3 skill as a system message, makes one local LLM call, and returns its text.

The node does not inspect the H3 generation graph, see reference media, know clip duration, or validate H3 output structure. `Auto` is an instruction to the LLM, not workflow detection. A supplied vision-capable LLM still receives only text through this node.

Sampling is fixed at 2,048 output tokens, temperature 0.2, top-p 0.8, top-k 20, repetition penalty 1.05, seed 0, and reasoning effort `none`. These are rewriting settings, not H3 diffusion settings. There is no evidence here that changing them would improve video quality.

The skill contains 734 lines / 2,702 whitespace-delimited words / 18,142 characters. Every request receives all modes and task rules. These counts are not tokenizer measurements.

## Keep the useful parts

Keep ambiguity management, ordinary actions expressed simply, extra mechanics for difficult interactions, clear ownership of camera motion, compact preservation instructions, and the distinction between semantic preservation and unchanged pixels. The earlier August 24 corpus synthesis already captured these ideas; this review does not claim them as new discoveries.

Keep the existing scene interpretation of `[Shot N]`: several camera cuts can remain inside one scene block. Increment the tag for a major scene/sequence boundary, not merely a new angle or framing. The initial review incorrectly recommended replacing this behavior with the official guide's per-cut numbering; that recommendation is withdrawn following verification of the community tests below.

Keep the shared local inference pipeline, node ID, existing input order and defaults, single STRING output, and generic Prompt Enhancer. The generic enhancer also loads this skill, so a skill update affects both entry points.

## Highest-priority improvements

| Priority | Finding | Proposed change |
|---|---|---|
| 1 | The skill tells the LLM to preserve an official image-alignment instruction without providing that instruction. FL timing requires information absent from the interface. | Bundle explicit mode-specific templates and provide optional effective duration. With duration unknown, avoid invented numeric endpoints; report missing information when strict official formatting requires it. |
| 1 | The backend ignores a streamed `finish_reason=length` and can return incomplete text successfully. | Raise an actionable truncation error in the shared stream parser. Never silently send a partial prompt downstream. Keep the existing string return contract. |
| 2 | Reference mode supplies six heading names but little guidance for their contents. There is no inventory of actual assets. | Add an optional compact reference/context text input. Define asset roles, target subjects, aliases, retention relationships, and the distinction between source audio reuse and voice/style guidance. Do not invent references. |
| 2 | Exact dialogue, visible text, and reference aliases are protected by general prose, without output verification. | Preserve these literal spans explicitly. Check clearly identified spans, supplied aliases, required sections, and timestamp bounds. Fail clearly or perform at most one bounded repair; do not silently rewrite ambiguous user content. |
| 2 | Selector combinations can conflict: `Semantic` with `Precise Action` or `Strict` is not clearly resolved. | Define precedence: explicit creative constraints and literal text first; explicit action-detail choice over task defaults; enhancement level controls editing intensity. `Auto` must never imply access to unseen media. |
| 3 | All 734 lines are sent for every mode; request validation only reserves a small generic margin and does not count the assembled system/user prompt. | After correctness fixes, send a short common core plus relevant mode/task guidance. Measure token use and reserve output space using the selected model's tokenizer where available. Preserve a complete guide for the generic enhancer. |

MiniMax's base guide supplies image-alignment templates and requires the effective duration for endpoint alignment. It also distinguishes spoken dialogue, voiceover, visible text, and separate audio layers. Its per-cut shot numbering conflicts with the community continuity tests below; documentation alone is insufficient grounds to override the existing scene-block behavior. Treat its other prescriptions as documented conventions to verify against observed behavior, rather than assuming they are necessary parser rules. [MiniMax base guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)

The reference guide separates reusable subjects from source assets and defines explicit visual/audio retention markers. A video containing sound does not automatically establish an audio reference. It also recommends 350–500 words for the generation-mode detailed description, so a compact variant would be an intentional departure needing evaluation, not an official requirement. [MiniMax reference guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)

## What newer H3 chatter changes

These are firsthand community reports, not independently reproduced measurements. The linked messages were fetched live and preserved, with available metadata and one-hop reply parents, in the adjacent evidence JSON.

- **A scene block can contain multiple cuts.** On August 25, Illynir reported a comparison between three numbered shot blocks and one block containing timed changes, with two attached result videos. The reported result favored the single block for spatial coherence. Their accompanying alley prompt contains two camera cuts inside `[Shot 1]`. Lumifel reported corroborating continuity benefits on August 26; HeadOfOliver reiterated the same approach on August 31. This supports retaining the current skill rule. The messages and attachment metadata were verified; the videos were not independently assessed here, and full experimental controls are not established. [Illynir's comparison](https://discord.com/channels/1076117621407223829/1532625331960152124/1541912339488448513), [prompt example](https://discord.com/channels/1076117621407223829/1532625331960152124/1541914224379306106), [Lumifel](https://discord.com/channels/1076117621407223829/1532625331960152124/1542230863364755587), [HeadOfOliver](https://discord.com/channels/1076117621407223829/1532625331960152124/1544113038225834094)
- **Dialogue needs conditional guidance.** Ryko reports more consistent speech without audio references and babbling when references are introduced. That motivates distinguishing voice guidance from timeline reuse and avoiding redundant audio instructions; it does not justify banning audio references. [Ryko, September 7](https://discord.com/channels/1076117621407223829/1532625331960152124/1546372137160540240)
- **Keep speaker IDs as a formatting convention without promising a cure.** foxydits reports little benefit in roughly 100 A/B comparisons; seitanism reports failures when IDs were omitted. Do not replace one universal rule with the opposite. [foxydits](https://discord.com/channels/1076117621407223829/1532625331960152124/1546280847370354830), [seitanism](https://discord.com/channels/1076117621407223829/1532625331960152124/1546280481623117874)
- **Timing and closed-mouth wording are not reliable silence controls.** foxydits reports improvement from several simultaneous changes; Ryko reports continued filler speech despite timestamps and closed-mouth instructions. The combined change does not isolate which wording helped. [foxydits](https://discord.com/channels/1076117621407223829/1532625331960152124/1546377927380308078), [Ryko](https://discord.com/channels/1076117621407223829/1532625331960152124/1546380975691276298)
- **Reference preparation can matter more than additional prose.** Ryko describes using depth references to avoid transferring unwanted identity. This is a workflow technique worth documenting alongside attribute transfer, not something the text enhancer itself can perform. [Ryko, September 7](https://discord.com/channels/1076117621407223829/1532625331960152124/1546580087246291075)
- **Do not turn concision into another absolute rule.** Ryko's limited cleanup/upscaling tests required both a good first frame and sufficient description of desired detail. Some tasks need expansion. [Ryko, September 7](https://discord.com/channels/1076117621407223829/1532625331960152124/1546561393023651861)

Older source checks remain useful: EkiHalkka reported late timestamped actions being compressed into short generations, and LukeG89 clarified one implementation's reference index mapping. These support providing real duration and preserving verified aliases. They do not establish universal timing or numbering behavior. [EkiHalkka](https://discord.com/channels/1076117621407223829/1532625331960152124/1538547587383169074), [LukeG89](https://discord.com/channels/1076117621407223829/1532625331960152124/1534526191887716392)

## Smallest useful upgrade

First revise the existing skill's contract: explicit templates, literal preservation, selector precedence, and audio roles. Retain the current scene-block and inline-cut behavior, document its evidence, and add regression cases for multiple same-scene cuts without extra shot tags. Add only optional duration and reference/context inputs, with defaults that preserve existing calls. Keep the current structured output as the compatibility baseline. Do not add numerous task presets or a mandatory second LLM pass.

Handle stream truncation separately as a narrow shared-backend correctness fix. Then add output checks and evaluate selective instruction loading. A compact output format and optional image input can follow only if tests show a useful improvement; direct media input introduces capability, preprocessing, and context costs.

For example, a five-second I2V request describing a stationary truck and an orbit should resolve camera ownership and the intended view without adding a location, wardrobe, score, or additional action. A clothing edit should bind the supplied identity and video references and describe the requested clothing change without manufacturing extra assets. These are proposed acceptance behaviors, not observed outputs from this node.

## Verification and acceptance plan

Current baseline: 59 existing GGUF tests pass. They establish infrastructure and payload behavior, not prompt quality. The H3 payload test mocks inference to return `compiled`; the skill test checks selected phrases and loading behavior.

A simulated SSE stream ending with `finish_reason=length` returned the incomplete string `integrated_multimodal_description: [Shot 1] She opens the` without raising. This confirms the truncation handling defect independently of any model output.

Before judging an upgraded enhancer, compare raw input, current enhancement, and proposed enhancement on eight cases: simple I2V motion; precise contact; stationary-object orbit; same-scene cuts; FL endpoints; clothing replacement; exact dialogue/voiceover; and two-speaker audio-reference conflict. Include already-detailed input and conflicting selector settings in text-only regression cases.

At the text stage, check preserved constraints and literals, alias validity, output completeness, appropriate format, unsupported additions, token use, and latency. At the video stage, hold checkpoint, conditioning, duration, sampler, guidance, LoRAs, caches, and resolution fixed, and use three paired seeds per case initially (72 clips across three prompt variants). Score adherence, identity, camera/continuity, action completion, and speech separately. Expand only ambiguous cases. Better-looking prose or a single attractive result is insufficient evidence of improvement.
